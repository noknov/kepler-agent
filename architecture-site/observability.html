运行观测

观测的作用是帮助判断系统正在等待什么、哪里出现失败，以及哪些结果已经保存。运行列表、健康检查、工具探测和模型追踪各有不同的数据来源，不能把某一个绿色状态当作整体正确的证明。

运行投影与轨迹

会话事件适合记录完整执行事实，但用户查询通常需要运行摘要和步骤列表。因此系统从事件生成运行投影，例如执行状态、耗时和步骤信息。这个查询结构便于展示，不是第二套能够覆盖原始事实的状态机。

例如，某次运行投影仍显示 running，可能是执行尚未结束，也可能是终态已经保存而投影没有更新。仅凭这一行数据，不能证明对应进程仍然活跃。

执行轨迹则把模型、工具、恢复和终态事件按关系重建，便于调查某一步。查看轨迹时仍需区分真实保存的结果与即时呈现片段。

健康检查

健康检查需要先说明检查对象。/livez 只说明进程存活；/readyz 检查该服务依赖和是否允许准入。进入 drain 后 readiness 失败，是停止接收新工作的信号，不表示已有工作全部结束。

依赖就绪也不能证明所有用户集成可用。例如，数据库和 Redis 都正常，某位用户的外部连接却已过期，工具仍可能被拒绝。真实任务还需要模型与所用集成共同成功。

运行、指标和管理接口属于对应服务，不能假设公开网关提供所有内部诊断。受保护接口使用配置的管理认证，管理凭据不应被随意转发给其他服务。

信号与证明范围

不同信号应配合使用。收件箱积压说明有待处理工作，但可能在等准入，也可能在等某个失效认领恢复；模型错误数说明网络或协议出现失败，但不一定导致最终执行失败，因为某次重试可能已经成功。

工具健康缓存来自限定探测，并受有效期约束。缓存缺失应表示不可用或未知，不能自动算作所有工具健康。追踪导出收到回执，也只说明批次发送得到确认，不保证下游索引已经完成。

说明示例

没有最终回复时的信号顺序

假设用户只看到“任务已接收”。先查持久入口是否仍在排队，再查对应执行有没有终态，最后查投递关联。

如果终态已经完成而投递失败，应修复投递。如果入口根本没有完成持久接收，就不能从运行列表为空推导出模型失败。本例描述调查顺序，不代表一次真实事故。

指标接口与时间范围

指标必须带时间和样本范围。某个接口统计最近一批运行，另一个接口统计选定时间窗口，它们的百分比和耗时可能不同。进程内计数在重启后还可能清零。

当前 JSON 诊断与 Prometheus 格式接口分别提供。使用接口前要核对格式、窗口、缓存有效期和历史范围；不能只因为路径里有 metrics，就把它当成长期时间序列。

错误、取消、等待用户和未完成属于不同结果。没有可计入样本时，错误率应保留未知；“没有错误样本”不是已经验证的零错误率。

日志、追踪与内容

诊断需要足够的关联信息，但不必默认复制全部任务内容。默认追踪属性记录会话、执行和工具等关联字段，不附带完整提示、工具参数、模型答复或凭据。

显式启用的内容记录器有独立的配置与大小、字段和脱敏限制。这是另一个数据出口，不能因为默认 trace 不带正文，就推断启用内容采集后仍然没有业务文本。

原始日志、评测文件、备份和外部追踪也分别有保留期与访问控制。清理当前会话或记忆，不会自动从所有这些系统删除相同内容。

用量与成本

用量说明模型报告使用了多少资源，预算用于限制还能消耗多少，金额估算再按配置费率换算。三者不是一个指标。提供方还可能使用不同的缓存和推理 token 口径。

一次逻辑请求失败后重试，可能有多次实际消耗。未知失败没有用量回执时，系统保留预算估算，不能直接计算为零。子任务用量汇总到主任务时，也需要避免再次与每次尝试重复相加。

如果部署没有配置费率，估算金额为零只表示估算参数为零。实际账单仍需向提供方核对，不能据此声称调用免费。
