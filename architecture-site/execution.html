执行过程

一次执行（turn）包含输入、模型轮次、工具调用和终态。执行器先取得会话处理权，再根据已保存事件推进状态。

实现基线 3599545 ↗

执行范围

一次执行由输入建立开始，到完成、等待、取消或失败终态结束。它可以包含多个模型轮次、网络尝试和工具调用。各标识的含义由概念与标识定义。

执行前置条件

  1. 入口确认用户、工作区和会话归属。会话标识本身不是认证凭据。
  2. 执行器取得会话处理权，并检查相同 TurnID 是否已有终态。
  3. 已有终态时，执行器恢复对应结果，不重新执行工具。
  4. 缺少终态时，执行器核对未完成模型请求和工具调用，并确保用户输入已保存。

TurnStarted 与 UserInput 是不同事件。只有开始标记而没有用户输入时，恢复仍需补齐输入。

执行状态

阶段主要记录后续动作
输入建立turn_started、user_input构造上下文
模型请求model_request_started 与完成或失败事件保存完整模型消息
工具执行tool_call_started 与结果事件保存结果并继续或结束
等待待输入或待批准终态按原调用和身份恢复
终止完成、失败或取消终态清理执行范围内状态并返回结果

上下文构造

每轮请求从会话事件生成模型消息。执行器纳入环境、当前输入、有效摘要、历史消息和工具定义，并在派发前检查完整请求预算。

用户输入中的图片可用于当前执行。持久化用户输入时，执行器将这些图片替换为文本说明。工具结果图片另有处理规则。

完整选择、预算、压缩和读取规则见上下文与证据。

模型请求

执行器依赖统一的 model.Client。产品配置提供的弹性客户端负责提供方重试、备用路径和熔断。一次逻辑请求可以包含多次网络尝试。

完整模型响应与流式片段分别处理。只有完整工具调用才能进入工具执行；参数片段不触发外部操作。

工具执行

  1. 解析工具身份和调用参数，检查已有结果。
  2. 检查能力策略、实际作用域和审批状态。具体工具验证业务参数。
  3. 取得并发名额和对应读写锁。
  4. 保存工具开始事件，再调用执行器。
  5. 保存结果或分类错误，按模型可见预算处理内容。
参数校验范围

当前执行器不提供覆盖全部工具的完整 JSON Schema 校验层。工具实现仍需检查边界值和业务前置条件。

追加输入与取消

追加输入在模型或工具轮次之间写入会话事件。排队输入用于后续执行；取消用于停止当前执行。三者具有不同状态，不能合并为一个“最后消息”字段。

等待会话处理权时的取消应及时返回。已经开始的执行在取消后仍需完成有界的终态写入与清理。

执行终态

类别触发条件处理要求
完成模型返回最终答复且没有需要继续处理的输入保存答复、用量与终态
等待输入或批准当前执行需要外部输入保留请求身份与原始调用
取消或超时取消信号或执行期限触发停止继续派发并执行有界清理
上限或预算耗尽轮次、上下文或执行预算不足明确结束，不追加一次未计入预算的总结请求
错误模型、工具或存储出现无法继续的错误保留分类及可核对的事件

终态写入使用独立的有界清理上下文。终态保存失败属于持久化故障，调用方不能报告持久完成。
