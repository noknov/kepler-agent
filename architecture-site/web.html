Web 接入

Web 将浏览器交互与服务端执行分开。浏览器提交用户输入并显示事件；服务端负责认证、会话归属、持久输入、执行准入和恢复。页面连接中断，不等于后台任务已经停止。

服务职责

浏览器界面不是执行器本身。用户点击提交后，请求经公开入口到达 Web 会话服务；服务端验证身份和 conversation 归属，保存输入，再按准入与队列规则推进。实际模型和工具运行在托管工作进程。

因此，浏览器负责维护草稿、连接与展示状态，服务端负责可靠的会话与执行事实。把“按钮恢复可点击”当成执行结束，或把页面还开着当成任务仍活跃，都会混淆这两层。

认证与会话归属

浏览器通过登录建立自己的会话身份。这个身份与 Slack 某条线程的身份不是同一个对象，也不同于用户授权 GitHub、GCP 等外部集成的连接。

用户请求某个 conversation 时，服务端先检查它是否属于当前用户允许的范围。知道 conversation ID 不能当作访问凭证。工具需要外部授权时，还要从正确的用户连接与实例选择凭据。

这种区分使“可以登录网站”和“可以读取某个外部资源”成为两项明确检查。前者成功不能证明后者已经授权。

准入与持久输入

服务端保存输入后，需要在可执行时认领它。工作进程已满时，不提前占住大量等待会话并消耗它们的重试次数。已经接收的任务则需要在执行结束后完成持久确认或释放。

查询会话时，数据库暂时不可用和数据库明确返回会话不存在，含义不同。前者应释放认领等待恢复；不能假装它是无效会话并确认丢弃。

同样，已有持久终态的执行可以按终态确认，不再重复执行审批、模型和工具。队列恢复依赖服务端记录，而不是浏览器是否还连接。

事件与重连

事件流让浏览器逐步看到文字和运行状态，但网络可能随时断开。断开后，界面需要从服务端恢复会话与运行状态，而不能假定“没再收到文字”就表示执行失败。

说明示例

刷新页面后的任务

假设用户提交了登录故障调查，随后刷新浏览器。后台可能仍在等待测试工具返回，也可能已经保存最终答复，只是页面尚未显示。

重新打开后，应根据会话和运行记录恢复展示。盲目再次提交相同任务，可能创建新执行并重复调查。

输入草稿、流式片段和连接指示属于界面状态。完整模型消息、工具结果和终态属于执行记录。两者可以短暂不一致，需要由重连与结果加载收敛。

关闭与恢复

服务准备关闭时，先在生命周期锁下阻止新准入，再等待已接收工作及其持久确认。只等模型请求结束不够，因为执行结果还可能需要写入、队列还可能需要确认。

到达共享关闭期限后，服务取消工作，再做有界清理。浏览器可能在这个过程中断开，但断开只是呈现变化。恢复时仍需读取服务端记录，判断执行已完成、已取消还是结果未知。

验证范围

Web 验证需要覆盖登录、会话访问、输入提交、事件重连、执行终态和用户集成。静态页面能够加载，只证明前端文件可访问。

例如，浏览器能显示对话列表，但工作进程无法连接模型提供方，新的任务仍不能完成。反过来，模型已经完成但事件流断开，则需要检查呈现与重连，不应先重跑模型。

现有认证、会话与恢复测试验证对应的边界；真实登录和一次实际模型响应仍需在选定部署上验证。
