模型协议与重试

一次模型请求可能经历连接、流式接收、协议完成判定、退避和再次尝试。应用需要判断哪些内容已经可靠取得、哪些可以重试，以及何时必须停止，不能只看 HTTP 是否返回。

请求与适配边界

执行器关心的是：给定一份上下文，能否取得一份完整模型结果。不同提供方却使用不同的请求字段、流式事件和工具格式。模型适配器将这些网络差异转换为内部的请求、响应、内容块、工具调用、用量和错误类型。

弹性客户端位于这条边界上，负责一次逻辑请求中的实际网络尝试。例如，请求第一次遇到暂时性故障，第二次成功，执行器仍应得到一份完整结果，而不是把两次尝试当成两条用户输入。

上下文是否选对、工具是否有权限，是其他模块的职责。把这些工作与协议解码分开，才能更换提供方而不重写会话恢复和工具策略。

协议与完成判定

网络连接结束只表示没有更多字节到达，不一定表示模型已经完成。连接可能正常结束，也可能在回答中途断开。适配器因此检查提供方协议中的结束回执，而不是把 EOF 一律当成成功。

文本与工具分别收敛

Chat Completions 需要明确的结束原因，单独的 [DONE] 或 EOF 不够。Responses 按原生项目回执和最终状态处理结果。Anthropic 按内容块索引连接开始、增量和结束事件。

工具参数尤其需要完整性。例如，一个 JSON 参数只接收了前半段，应用不能自己补完后执行。工具身份在流式索引中发生冲突，或者参数无法形成可接受的完整对象时，应返回协议错误。

说明示例

响应未完整接收

假设模型正在生成读取文件的参数，连接在文件路径中间断开。此时应用只有一段不完整字符串，没有一个可执行的工具请求。

正确处理是保留协议失败，按重试条件决定是否重新请求模型；不能猜一个路径，也不能因为已经看见工具名称就启动工具。

重试、备用路径与熔断

重试用于处理可能短暂恢复的失败，例如明确的临时服务故障或限流。它会再发一次网络请求，所以必须同时受尝试次数和剩余执行时间限制。尝试次数包括第一次调用。

重试之间采用有上限的退避和抖动。退避让受压服务有恢复时间，抖动避免多个执行者同时重发。用户取消时，等待也需要结束，不能等完固定延迟后继续请求。

备用路径是切换到已配置的其他模型或提供方。它不是所有错误的通用修复：权限不足、配额用尽和未知错误要按明确分类处理。主要提供方的熔断也只是暂时停止继续尝试该路径，不证明备用路径一定健康。

输出提交与工具执行

重试还受输出提交限制。应用向接收器成功提交非空文本后，用户可能已经看到这段内容。此时从头再请求一次，可能生成另一份措辞和结论，最终在界面上拼成两份回答。

因此，弹性客户端把已提交可见文本作为停止透明重放的边界。这里说的是向呈现接收器提交，不等于消息已经最终投递到用户，也不等于完整模型答复已经保存。

说明示例

已输出文字后断流

假设界面已经显示“登录失败与会话校验有关”，随后连接中断。重新请求可能得到“数据库连接失败”的另一份回答。直接拼接会让用户无法判断哪份结论可靠。

系统应保留已提交状态和分类失败，由对应入口处理错误与呈现恢复。若没有完整结果，就不能把片段当成已验证结论。

工具参数增量和用量事件不等于可见答复，也不等于工具已经运行。执行器等待完整模型响应后，才进入工具检查与执行。

网络尝试与资源预算

父任务、子任务和压缩器都可能请求模型。如果每个调用方只限制自己的一小部分，进程合起来仍可能超过提供方或本机承受能力。因此，实际网络尝试共享进程内的准入控制。

一次尝试取得名额后才访问提供方。进入退避时释放名额，避免失败请求一边等待，一边占满其他工作的通道。这个限制保护单个进程，不自动形成多副本共享的租户配额。

token 预算与并发名额也不同。并发限制同时有多少请求，预算限制可以消耗多少估算用量。每次尝试先预留，收到提供方用量后结算；没有用量回执的失败需要保留估算，不能直接算作零。

最终运行用量、逐尝试预算扣减和提供方账单有不同口径。缓存 token 与子任务用量要按结构化记录归并，不能把逻辑请求总量再与每次尝试重复相加。

错误分类与恢复条件

错误分类决定恢复动作。HTTP 状态、提供方明确错误码和协议状态都可能参与判断。诊断消息的措辞可以帮助人工调查，但不能仅凭字符串里出现“稍后再试”，就把任意错误变成可重试。

  1. 临时故障或明确限流：检查是否尚未提交文本，以及次数和期限是否允许，再退避重试。
  2. 认证、权限或配额问题：停止不适用的重试，核对对应配置或账号能力。
  3. 协议不完整：不发布未完成工具调用，保留分类错误。
  4. 文本已经提交：停止从头透明重放，保留执行与呈现状态。
  5. 所有允许路径都不可用：以明确原因结束，不把空结果标为成功。

实际行为由 packages/agent/model/resilient.go 与对应回归测试定义。提供方适配器还负责各自的完成回执规则。
