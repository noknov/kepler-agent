CORE / CONTEXT & MODEL

提示内容、上下文与模型

模型质量与生产可靠性共享同一个入口：最终发给 provider 的那份请求。它不仅包含用户原话，还包含分层提示、运行环境、摘要、工具定义和工具结果。Kepler 把这些内容先转换成 provider-neutral 的 canonical messages，再把协议差异留给适配层。

提示 分层合并历史 事件投影容量 保守估算失败 先看提交边界

模型一次能够看到什么

一次请求不是把数据库里所有内容原样塞给模型。执行器每轮重新生成系统说明、会话消息和当前工具定义；只有会影响下一步判断的内容进入模型请求。

组成会影响什么是否进入长期 transcript
系统说明身份、证据纪律、安全边界、操作规则由提示目录和运行配置重建，不作为会话消息追加
运行环境日期、时区、workspace roots、本次作用域按请求生成；不依赖入口的旧环境缓存
会话消息用户意图、已完成答复、工具结果是；图片二进制会被替换为可解释的文本说明
工具定义模型能否提出某个调用以及如何填写参数目录是 profile 状态；激活状态按 turn 清理
流式 delta入口实时展示否；完整 assistant message 和 lifecycle 才是恢复依据

提示不是一段越来越长的字符串

提示内容按稳定性和责任拆开。越靠近业务环境、变化越频繁的内容，越不应该写进核心系统说明；否则每次部署变化都会扩大上下文、破坏缓存并难以定位行为回归。

层典型内容装载/覆盖规则变更风险
Core kernel身份、保密、证据、自主执行、沟通和安全packages/prompts/defaults/system.md，提交到仓库影响所有 surface；需要跨产品回归
Rules调查方式、写操作约束、验证要求、调试纪律rules/*.md 按目录读取并合并可改变工具选择和结束前行为
Tool guidance用途、参数、路由提示和安全说明随工具 descriptor 及 tools.json 应用只改善选择提示，不能扩大 policy 权限
Skills完整工作流、专项检查和验证步骤基础 prompt 只放名称/说明，按需 skills-load按需加载仍要视为不可信历史/外部输入边界
Private overlay仓库别名、环境映射、私有 runbook 入口PROMPT_DIR 叠加在 public defaults 上不能把凭据或大段 incident 历史放入每次 prompt

提示修改的判断

如果一条文字包含某个公司的仓库、workflow、租户或私有服务，它通常属于 overlay 或 workflow，而不是系统 kernel。提示可以约束模型行为，但不能代替工具的 schema、服务端 allowlist、workspace 检查和上游权限。

会话事件怎样变成模型上下文

Transcript 同时包含恢复所需的生命周期事实和模型真正需要的对话内容。BoundedProjector 通过事件类型、摘要覆盖点和完整交互分组把两者分开。

  1. 计算输入预算。总 MaxTokens 减去 ReserveTokens；预留给模型输出、工具定义和 provider 差异。配置差值不合理时才退回总上限。
  2. 选择最近有效压缩。只接受带有向后覆盖边界的 covers_through。坏摘要不会悄悄遮住原始消息，避免数据损坏变成事实丢失。
  3. 筛选可投影事件。UserInput、SteeringInput、AssistantMessage、ToolCallCompleted/Failed 形成 canonical messages；锁、step、projection 和 trace 事件留在运维层。
  4. 按 TurnID 聚成完整 group。一个用户请求及其 assistant tool call/result 是一个不可拆分单元。这样裁剪不会留下模型提出过调用却没有相应结果的上下文。
  5. 从最新 group 向前加入。最新 group 必须保留；更早 group 只有在预算内才进入。不能连最新请求一起丢掉来“解决”超限。
  6. 叠加当前环境和工具。环境片段在 system messages 后插入；当前 tool catalog 的 active definitions 与投影一起交给模型。
估算不是 provider tokenizer估算器按 ASCII、中文字符、结构、图片、artifact 和 tool result 做保守近似。它只能提前发现大多数超限；provider 仍可能因自己的 tokenizer、隐藏 reasoning 或工具协议拒绝请求。

长对话压缩怎样避免语义断裂

压缩不是删除旧行，也不是覆盖 transcript。它产生一条新的、带覆盖序号的摘要事件；原始历史继续存在，摘要只是以后投影的入口。摘要还会被明确标为不可信 transcript data，避免模型把历史里的命令当成系统指令。

发现可丢弃范围
投影器按完整 group 计算 Dropped 和 CoversThrough；最近一轮不作为旧历史压掉。
准备安全输入
图片替换为说明文本；历史中的 prompt injection 不获得 system authority。
分块压缩
如果压缩输入本身过大，按用户边界分块，多轮归并；达到内部轮数上限则返回错误。
生成摘要
保留用户意图、决策、证据、路径、工具结果、约束和未解决事项；不发明事实。
提交摘要事件
写入 compaction_created 和 covers_through，不修改任何旧事件。
重新投影
从最新摘要继续加入未覆盖事件；若 provider 仍报 context limit，则强制收紧后再请求。

压缩会带来什么代价

压缩本身也是一次模型调用，增加 token、延迟和 provider 依赖。摘要错误可能让模型失去细节，因此需要保留原始 transcript、可从 coverage 定位被压缩范围，并在关键工作流中让工具结果带有稳定引用而不是只依赖摘要文字。

模型接入层负责协议差异

Runtime 依赖 model.Client，而不是某家 SDK。Provider adapter 将请求字段、消息块、tool calls、SSE 流和错误映射为统一模型契约；这样切换协议不需要重写会话、工具或恢复逻辑。

Provider 差异Canonical 表达必须保留的诊断信息
chat/completions、responses、Anthropic messagemodel.Request 与 model.Responseprovider、model、response ID、finish reason
不同 tool/function 格式model.ToolDefinition、ToolCall稳定 CallID 和原始参数字节/大小
SSE delta 类型不同started、text_delta、tool args、usage、completed事件类型、item ID、response ID，不默认存完整内容
缓存 token 口径不同model.Usage 的 cache fields是否已计入 input，避免成本重复计算
HTTP 状态和错误体不同typed model.Errorkind、retryable、status、受控错误信息
结构化引用挂在具体 Content block 的 citationsURL、标题、字符范围；呈现由 surface 决定

Provider adapter 可以保留 raw metadata 供诊断，但不能把完整凭据、prompt、工具参数或用户文本无条件放进 span 属性。模型返回的内容仍是模型内容，不会提升为系统策略。

重试、备用模型和熔断只在一个边界统一处理

ResilientClient 是 provider attempt 的唯一弹性边界。不要把多个 ResilientClient 嵌套起来，否则一次请求的尝试次数和截止时间会乘法膨胀，观测也无法回答“到底请求了几次”。

决策判定依据记录方式
重试typed transient、rate limited、unavailable 或 protocol；未取消且剩余预算足够同一 logical request 下增加 attempt，记录等待和结果
不重试invalid、authentication、context limit（交给压缩）、cancel、deadline结束该路径并归类错误
fallback主 provider 可 failover、备用已配置、尚未提交用户可见文字保留 primary/fallback provider 与 model 关系
熔断同一 provider/model 连续失败达到阈值，进入 cooldown新请求快速返回 circuit_open，不占用下游资源
空响应恢复Response 没有 content 且没有工具调用，使用 runtime 的独立空响应预算记录 model_failed；成功前不产生空 final
逻辑请求和网络尝试不是一对一一次 step 可能先发 primary、等待退避、再发 primary retry，最后切 fallback。成本、延迟和 provider 事故分析必须同时统计 logical request 与 attempt，不能只看 turn 数。

流式输出的提交边界

流式事件主要服务于展示。Runtime 会把 delta 送给 sink，但只把完整 assistant message、model lifecycle 和最终状态作为 canonical facts。这样 transcript 不会按 token 数线性膨胀，projection 也可以在事件重放后重建。

首段文字前

模型仍处于可安全重试的阶段；provider 临时故障可以 retry/fallback。

首段文字后

输出可能已被 Slack/Web/CLI 展示；停止 retry/fallback，防止两份答案拼接。

工具调用 delta

Runtime 等待完整响应后才执行工具；工具 delta 本身不等于外部副作用。

Sink 故障

呈现失败与模型完成是两件事；保留完整答案，交给 surface 的 delivery fallback。

如果产品把某些中间文本交给用户，就必须明确它是否改变输出提交语义。当前共享实现以非空文本 delta 为提交点，不能在不同 surface 私自采用“收到任意 stream event 就重试”的规则。

模型相关的生产推演

提供方返回 429，但队列也在增长

诊断把 provider attempt、429、retry delay、circuit 状态和 inbox backlog 放在同一时间线上。429 期间提高 worker 数只会制造更多受限请求。

动作先控制入口并发和 retry fan-out，确认 fallback 是否真的可用，再决定是否调整 provider 配额或路由。

提示更新后，同样输入的工具选择变了

诊断比较 prompt_hash、工具目录版本、激活列表、模型名和 workflow scope；不要只比较最终自然语言。

动作保留静态 prompt 与 dynamic context 的摘要，使用代表性请求做回归。工具选择改变不代表 policy 已改变，必须分别验证。

压缩后模型“不记得”关键路径

诊断定位 compaction_created 的 covers_through，检查被压缩的工具结果是否只有大段文本而没有 artifact 引用，检查摘要是否在未完成交互中切断。

动作调整工具结果外置和摘要字段，不直接放宽上下文上限来掩盖信息结构问题。

UI 没有收到流，但运行记录显示完成

诊断先查 canonical transcript 和 run terminal，再查 stream sink、SSE/Slack delivery。运行完成只说明 Core 终止，不说明用户看到了内容。

动作走入口的最终消息补偿或重连逻辑；不要重新执行模型和工具。
