产品入口

本地命令行

用户启动命令后，Go 程序完成登录信息、工作目录、本地配置和会话选择，再启动 TypeScript 终端界面。终端界面另外启动一个 Go 应用服务子进程，通过标准输入输出交换结构化消息。界面管理交互和显示，模型循环、工具权限与会话存储仍由 Go 端完成。

01

三个进程角色

命令入口不会把整个执行器编译进 TypeScript 前端。它只把访问令牌、服务地址、工作目录、模型、输入处理方式和待恢复会话放入子进程环境。这样终端渲染可以独立迭代，执行权限仍留在 Go 端。

02

从命令启动到出现输入框

  1. 解析工作目录和本地状态目录。工作目录转换成绝对路径。没有指定状态目录时使用本地产品约定的位置。
  2. 处理恢复请求。用户要求继续旧对话但没有给出编号时，Go 端读取本地会话列表，选取最近记录；没有历史则直接报告。
  3. 选择界面程序。优先使用显式指定的入口，其次查找与可执行文件一起打包的界面，再在源码目录中寻找已构建文件或开发入口。
  4. 启动终端界面。界面继承当前终端的输入、输出和错误流，因此能接收按键、控制备用屏幕并在退出后恢复终端。
  5. 界面启动应用服务。应用服务使用当前工作目录，标准输入和输出连接到前端；错误输出只在调试模式转发，避免普通日志破坏全屏渲染。
  6. 完成协议握手。前端确认双方支持同一版通信能力，随后创建新会话或读取指定会话的历史，最后把输入框切换到可用状态。
03

前后端通过一行一条消息通信

前端为每个需要答复的请求分配递增编号，把消息编码成单行 JSON 写入子进程。等待中的请求保存在内存映射里；返回消息按编号找到对应的等待者。超过等待时间仍未返回时，前端移除等待项并显示超时。

开始执行若遇到服务暂时繁忙，前端会进行有限重试并逐次延长等待；其他错误直接返回界面。应用服务自身限制同时活跃的执行数量，也拒绝同一会话同时开始第二次处理。

04

界面状态围绕一段对话组织

界面状态保存什么变化时机
已完成消息用户消息、模型完整回复和系统提示提交输入、恢复历史、工具结束或整次处理结束
正在生成的文字模型目前返回但尚未结束的文字收到每个文字片段时追加，处理结束后清空
当前工具调用编号、显示名称和精简参数工具开始时加入，成功或失败后移除
处理状态是否正在执行、当前处理编号收到开始与结束通知
连接状态连接中、可用或子进程失败协议握手和子进程退出
待批准动作工具名称、参数摘要、原因和调用编号收到批准请求后设置，用户作答后清空
等待队列忙碌期间选择稍后处理的用户输入提交时加入，当前处理结束后依次取出
滚动状态是否停留底部、未读分界线和最近手动滚动时间滚轮、翻页键、跳到底部和输入动作

正在生成的文字没有每次都塞进完整消息数组。它使用单独状态显示在消息列表下方；收到最终结果后，前端从流式文字、结束负载和完整消息条目中选择最完整的一份，只追加一次最终模型回复。这样可以避免同一答案在界面里重复出现。

05

终端页面怎样组成

顶部信息显示项目标识、当前工作目录、模型、用户和缩短后的会话编号。终端高度较小时切换为紧凑标题。
消息区域使用虚拟消息列表显示旧消息、模型回复和系统状态。消息区域可独立滚动，不会把输入框推离窗口。
流式回复在终端支持稳定光标更新时逐片段显示；遇到已知光标兼容性问题时采用更保守的刷新方式。
工具活动正在运行的工具显示闪烁圆点、友好名称和精简参数；结束后变成一条成功或失败记录。
等待提示模型还没有输出文字、也没有可显示工具时出现动态等待提示；一旦有实际内容便让位。
固定输入区斜杠菜单、批准面板和输入框固定在底部，不属于滚动历史。

工具参数不会原样铺满终端。界面优先提取任务、命令、路径、查询或网址等能说明动作的字段，压缩为一行摘要；内部范围字段不优先展示。常用文件和搜索工具还会转换成简短的显示名称。

06

输入在空闲和忙碌时有不同去向

空闲时提交的普通文字立即加入消息列表，并向应用服务发起一次新处理。以斜杠开头的内容在前端直接执行：帮助、查看状态、清空当前显示和退出不需要模型参与。输入框单独保存文字与光标位置，敲键不会让整个虚拟消息列表重新渲染。

加入当前处理

忙碌时的新输入立即显示，并送入当前执行。执行器会在下一个稳定边界读到它。

排在后面处理

忙碌时只放入前端等待队列。当前处理结束后，界面自动取出下一条并开始新的处理。

中断当前处理

正在执行时按下中断快捷键，前端请求应用服务取消当前处理；空闲时的同一按键仍由输入框负责。

输入焦点会在出现批准面板时让出，避免用户继续打字却误以为在回答工具批准。连接尚未完成、会话建立失败或输入为空时，界面不会发起执行。

07

需要批准的工具会暂停在具体调用上

应用服务收到本地权限层的批准请求后，把本次处理、会话和工具调用的关联通知前端。批准面板显示工具名称与参数摘要，并接受四种决定：只允许这一次、当前会话允许、当前项目允许、拒绝。

  1. 工具执行器提出批准请求。Go 端以当前处理编号和工具调用编号建立等待项。
  2. 前端显示批准面板并暂停普通输入焦点。按键直接映射到明确的批准范围。
  3. 应用服务核对等待项。找不到对应调用或同一请求已经回答时拒绝，不把批准应用到其他工具。
  4. 本地批准存储记录范围。会话级和项目级决定可供后续权限判断使用；实际路径和工具影响仍会再次检查。
  5. 原工具调用继续或返回拒绝。前端清空批准面板，恢复输入。
08

流式输出期间仍然可以阅读旧内容

消息区域记录用户是否主动离开底部。用户向上滚动后，新文字不会强行把视图拉回底部，而是在历史中保留未读分界。用户主动跳到底部、提交新消息，或在没有刚刚手动滚动的情况下开始输入，界面才重新跟随最新内容。

大量流式更新时，已完成消息可以使用延迟值降低重新排版频率；当前文字仍单独更新。全屏布局把滚动区与底部输入区分开，终端尺寸变化通过统一尺寸上下文传给组件。备用屏幕退出时恢复原终端内容，鼠标滚动只在全屏模式接管。

这部分直接影响可用性如果每个文字片段都重建完整消息数组并强制滚到底部，长会话会越来越卡，用户也无法在模型工作时阅读前文。当前状态拆分同时处理了渲染开销和滚动控制。
09

无界面模式绕过终端前端

非交互运行不启动 TypeScript 界面和应用服务。Go 命令直接组装本地执行器，读取标准输入或命令参数，按普通文本或逐行 JSON 输出事件。工具、工作区安全、批准规则、上下文和会话记录与交互模式共用；不同之处只是输入输出适配和批准范围由命令参数预先决定。
