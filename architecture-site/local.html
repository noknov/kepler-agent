本地 CLI 与 app-server

本地产品在用户选定的工作区执行工具，使用 JSONL 保存会话。交互式 CLI 与 stdio app-server 使用同一本地产品配置和共享执行器。

工作区与权限

--cwd 选择本地工具工作区。读写根、敏感路径、审批与操作系统沙箱共同约束工具访问。

本地审批绑定具体调用及其参数，不等于允许任意后续命令。本地会话锁跨进程保护整个执行，事件文件锁只保护短暂读写。

登录与模型配置

本地客户端从已认证网关取得模型启动配置。当前 CLI 不通过直接的 provider 或模型密钥参数替代这一路径。

CLI 登录与外部集成连接分别授权。配置文件用于本地限制、提示、技能、MCP 和工作区规则，不作为操作员提供方密钥的分发渠道。

协议与准入

app-server 使用 stdio JSON-RPC，提供 thread 创建、恢复、分叉和 turn 启动、追加输入、停止等操作，并发送 item 事件。

活跃执行数量受本地准入上限约束。容量满时返回明确的过载错误。分叉目标必须为空且未处于活动状态，不能直接向已有会话追加复制历史。

连接生命周期

stdio 连接拥有已接收执行的上下文。EOF 或输入错误会取消活跃工作。服务等待执行器完成有界的事件清理，再释放工作区和依赖。

本地 stdio 的准入不是托管持久收件箱。不能据此承诺进程退出后所有未处理输入都可恢复。

打包与验证

交互式包包含启动器、app-server 和终端前端，需保持相对目录结构。部署仓库负责打包。普通交互包依赖 Node，便携包另行携带运行时。

验证需区分 Go 构建、前端类型范围、交互测试与真实沙箱行为。无界面结果不能单独证明终端交互可用。
