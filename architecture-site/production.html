故障诊断

诊断先核对失败位置和持久记录，再选择恢复动作。已完成的执行、结果未知的外部操作和投递失败需要不同处理。

执行与投递的故障边界

现象核对记录处理
入口已确认但无答复收件箱认领、会话事件、终态、投递记录区分尚未执行与已执行但投递失败
模型输出后断流网络尝试、输出提交和完整消息不从头透明重放另一份答案
工具超时且无结果工具开始、执行标识与下游状态保留未知，查询实际结果后决定重试
运行列表缺少步骤权威事件与投影状态恢复投影，不重跑工具

期限与处理权

期限或锁保护对象到期或失效后的处理
入口响应期限平台请求接收避免等待完整模型执行后才响应
任务认领租约当前队列处理者按所有者和到期条件接管
会话执行锁同一历史的执行顺序取消旧执行者并重新对账
执行 deadline模型、工具和子任务停止继续派发并清理
关闭宽限期已经接收的工作到期后取消并进行有界收尾

积压与资源等待

现象检查对象处理依据
任务长期未被执行持久接收、认领、准入和可用工作进程定位工作是否已被接受及谁在处理
模型持续限流错误分类、实际尝试数和退避按提供方限制降低实际请求压力
工具等待增长工具并发、连接池和下游配额调整实际受限资源，而不是同时放大所有上限
界面无更新权威终态、事件流与最终投递分离执行恢复与呈现恢复

诊断依据

  • 记录会话、执行、网络尝试和工具调用标识，避免混用不同层级的 ID。
  • 记录应用与配置版本、时间、错误分类和相关脱敏日志。
  • 先验证依赖与状态，再执行恢复。不要把重启作为所有故障的默认处理。
  • 同一次未知外部写入需要下游证据，模型报告或哈希本身不能证明完成。

Schema 与发布

  1. 记录应用和配置版本，核对增量迁移兼容性。
  2. 验证备份可恢复，再应用所需迁移。
  3. 启动匹配的应用版本，检查服务依赖和真实请求。
  4. 故障回退时，分别评估代码、数据库与已产生的新数据。

应用运行时不执行 DDL。新装 schema 与增量迁移不是同一种升级方式。具体部署命令由 部署仓库 维护。

验证范围

验证覆盖范围
单元与契约测试对应输入、状态转换和边界
数据库与 Redis 集成测试显式测试存储上的持久行为
沙箱测试当前操作系统上的访问限制
真实模型与产品请求实际凭据、路由、模型和投递
备份恢复演练指定备份在隔离目标中的数据恢复

构建成功不等于真实请求成功。健康检查不等于完整业务验证。不同产品的验证结果不能直接互相替代。
