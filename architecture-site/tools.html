工具与策略

模型提出工具调用。执行器检查调用身份、能力策略和实际作用域后，调度工具并保存结果。工具可见性、用户确认和执行权限是独立条件。

工具声明

声明含义限制
名称与参数稳定调用身份及输入结构模型生成的参数仍需验证
效果 / effects读、写、网络或特权影响用于策略决策，不能从检索结果猜测
可见性 / exposure默认启用、延迟发现或关闭只控制目录可见性
并发属性是否允许安全并行修改共享资源的工具不能错误声明为只读并行
作用域 / scope服务端提供的会话、用户和工作区身份不能由模型参数替换

发现与激活

tool_search 的搜索操作只返回目录信息。激活操作使用确切注册名称，并将候选工具定义与确认结果一并纳入上下文容量检查。激活失败时保留原有目录。

工具发现采用词法检索。检索命中、名称匹配和激活成功均不代表本次调用获准执行。

调用流程

  1. 按调用标识检查已有结果，避免恢复时重复执行已记录调用。
  2. 解析调用并验证参数、业务前置条件和实际目标。
  3. 按能力策略决定允许、拒绝或等待批准。
  4. 取得并发名额与锁，保存开始事件。
  5. 执行工具并保存结构化结果、错误和证据引用。

授权与审批

托管能力策略由服务端配置决定。用户确认不能新增宿主机权限。写工具需要对应效果声明及确切的操作员允许项。

本地审批绑定原工具调用、参数、用户和会话。恢复时重新检查策略；模型重新生成的另一组参数不能继承原批准。

文件、命令与网络边界

边界执行要求
路径解析实际路径和符号链接，检查工作区与敏感文件策略
命令按 argv 执行；命令风险匹配不能替代操作系统隔离
沙箱本地使用 macOS Seatbelt 或 Linux bubblewrap；可用性需实际验证
网络对应网络工具检查协议、主机、解析地址和重定向目标
凭据按集成作用域使用，不能自动传入任意命令子进程

并发与资源限制

执行器在创建执行 goroutine 前取得并发名额。允许并行的调用共享读锁，其他调用使用写锁。工具内部的并发和下游连接池仍需单独限制。

执行器按工具声明选择锁。错误的并发声明可能导致数据竞争，锁本身不能修正声明。

结果与证据

模型可见结果受单项及批次总预算限制。截断通过 Truncated 等结构化状态告知模型。外置结果使用受作用域限制的引用读取，不能把任意宿主机路径当作证据入口。

历史结果遮蔽与新结果截断是不同阶段。前者调整后续上下文，后者限制当前工具输出。原始证据是否保留取决于对应存储机制。

恢复与重复失败

状态处理
调用已有结果复用已保存结果
已生成但未记录开始恢复写入 execution_not_started
已有开始但没有结果保留 execution_interrupted，不自动重发
相同调用重复失败当前执行内累计失败，达到阈值后熔断；成功清除该调用计数
执行结束清理该执行的熔断状态

外部写入与会话事件提交不是跨系统事务。安全重试取决于下游幂等约束或结果查询能力。

MCP 连接与信任边界

MCP 路由器使用配置、凭据指纹和调用作用域选择会话。凭据变化、租户变化或缓存到期后，需要重新握手。缓存不能替代调用授权。

远端 readOnlyHint 是工具声明，不是已验证的实际行为。未知工具写入失败不能因连接重建而透明重发。执行隔离、出站网络策略和凭据范围需要分别成立。
