CORE / TOOLS & POLICY

工具、权限与执行

工具把模型的判断连接到文件、代码仓库、外部服务和本地命令。可靠的工具系统不能只回答“模型能不能看到这个函数”，还要回答“当前用户能否调用、真实目标是什么、是否可以并发、失败后能否重做，以及结果如何被限制”。

描述 告知模型Policy 决定授权Runtime 控制调度Tool 负责边界与副作用

工具注册时就要说清楚影响

Descriptor 是工具进入系统的静态契约。它不等于权限，但缺少它就无法安全地进行策略判断、并发调度、目录暴露和结果治理。

字段回答的问题错误声明的后果
Name / schema叫什么、参数是不是 object、必填和允许值是什么模型调用歧义；注册时直接拒绝无效 schema
Effects只读、改 workspace、改外部系统、网络或 privileged安全边界失真；ReadOnlyPolicy 可能错误放行或拒绝
Exposureeager、deferred、disabled，是否默认进入模型上下文上下文膨胀或能力意外不可用；不会因此获得授权
Parallel能否和其他明确安全调用同时执行mutating/privileged 工具在注册时不允许标为并行
Exclusive是否必须成为一批调用中的唯一工具需要暂停/用户输入时，可能先执行同批写操作
Timeout单次执行的局部时间上限慢下游拖住整个 session；没有 deadline 的调用难以恢复

工具从目录进入模型上下文

产品启动时组装 Catalog。轻量常用工具可以 eager；较重、依赖连接或只在专项任务使用的工具以 deferred 形式保留。模型先通过 tool_search 列出稳定分类或做词法搜索，再用准确名称/分类激活。

  1. 注册时校验 descriptor。名称、effects、schema 和 parallel/exclusive 组合不符合契约时启动失败，而不是等模型调用时才暴露隐患。
  2. 按 surface 和依赖过滤。没有当前连接或不适合当前入口的工具不进入 catalog；这是可见性和组装问题，不是 operator authorization。
  3. 稳定地做发现。搜索返回稳定名称、分类和精确描述；排序改变不应让一次搜索随机暴露不同能力。
  4. 按 session 激活。激活使用准确名称或分类，后续模型 step 才看到 definitions；请求结束时释放。
  5. 执行时再次查找。即使模型看过 definition，调用时仍要 GetActive、参数解析、策略判断和目标边界检查。

一次工具调用的完整路径

模型产出的 tool call 是不可信输入。Runtime 在真正调用 Execute 前完成所有无副作用检查，并把开始、结果和错误分开持久化。

  1. 按 CallID 查找已有结果。同一 turn 中有成功或失败结果的调用直接复用，不重新访问外部系统。它是恢复级幂等，不是全局分布式事务。
  2. 确认工具仍 active。工具存在、未 disabled，并且是 eager 或已被当前 session 激活；未知工具形成结构化错误返回模型。
  3. 校验参数和目标。schema 负责形状；具体实现负责路径、资源 ID、网络目标、scope 和业务约束，不能把 JSON 解析成功当成安全。
  4. 检查 exclusive。独占工具与其他调用混合时整批不执行，返回 mixed_exclusive_tool_batch，避免“等待用户”的调用和写操作交错。
  5. 请求 Policy 决策。allow 继续；deny 写入 policy_denied；require approval 写入 ApprovalRequested，并由明确的批准流程继续。
  6. 安排并发和锁。parallel 调用取得总并发名额并共享读锁；其他调用取得写锁。并发名额在启动 goroutine 之前取得。
  7. 先记录 ToolCallStarted。这是外部动作前的 durable marker。写入失败时不应继续执行，因为恢复无法判断边界。
  8. 执行、规范化和限时。每个工具可以有 timeout；panic、空结果和普通错误转换为结构化失败，保留 error code、duration 和 trace 关系。
  9. 按请求顺序记录结果。并发完成顺序不改变模型上下文顺序。ToolCallCompleted/Failed 写入后，下一 step 才会重新投影。

权限层要检查实际作用域

两种 profile 共用 descriptor 和调用协议，但控制对象不同。Hosted 权限由 operator policy 负责；Local 权限则把 workspace、批准和 OS sandbox 组合起来。

方面Hosted profileLocal profile
控制对象服务端 workspace、服务凭据、用户连接和外部资源用户选择的本地 workspace、本机进程和本地连接
写权限精确工具名 operator allowlist；终端用户批准不能扩大主机权限workspace policy、scoped approval 和 sandbox
身份用户/租户作用域与 operator credential 分开本地用户和当前项目作用域
连接user_connections 中的每用户 OAuth token 再次核对 provider scope本地配置/连接不能绕过工具自身检查
入口标签限制工具适用 surface，不构成授权UI 提示只是展示；解析后的目标和批准才有效
失败策略拒绝是结构化工具错误或不可用能力可等待用户批准，但批准绑定原始 call，不接受替换参数
批准的安全语义

批准流程保存的是已经请求的具体 ToolCall。恢复时按 TurnID + ToolCallID 找回原始参数，再重新检查当前 policy；界面不能把“批准”变成提交一组新参数的通道。

本地文件、命令和网络怎样限制

路径解析

输入路径先清理并转绝对路径，再检查是否在 workspace roots 内。已有目标解析 symlink；新目标检查最近存在的父目录，避免父级 symlink 把写入导出到根目录外。

敏感文件

路径边界之后仍检查凭据、密钥和其他敏感位置。通过 workspace read 测试不代表 Git、诊断或命令工具也能安全访问同一文件。

argv 执行

命令以参数数组启动，不把模型字符串交给 shell。命令风险匹配只提供保守信号，不是 shell parser，也不能单独承担隔离。

OS sandbox

macOS Seatbelt、Linux bubblewrap 按调用需要开放读写和网络。沙箱不可用时正常策略拒绝；绕过是显式开发 escape hatch。

网络目标

检查 scheme、hostname 和地址；DNS 解析后再次拒绝 private/loopback/link-local 等目标，重定向也重新验证，且不静默使用 proxy 环境变量。

进程后代

命令的子进程继承可见环境和 sandbox 边界。不要把本地登录令牌自动放入子进程，也要测试子进程是否能绕开父命令的限制。

并发只由事实声明驱动

“模型一次返回多个调用”不等于“它们互不影响”。并发属性由 descriptor 声明，并由 Runtime 用读写锁和 bulkhead 落实。

Runtime 在创建执行 goroutine 前占用并发名额，所以一次异常大的调用批次不会瞬间耗尽 worker。工具内部如果要对路径数组或远程资源 fan-out，还要使用自己的上限；当前 MapOrdered 将内部 worker 限制为固定小值。

并发声明是正确性契约如果一个工具实际上会修改共享资源，却声明为 parallel，锁只能忠实执行错误声明，无法挽救数据竞争。新增 parallel 工具必须测试真实重叠行为、取消和下游限流，而不是只测 descriptor 字段。

工具结果怎样进入下一次模型判断

单个结果和整批结果分别受 inline budget 约束。结果治理同时保护模型上下文、transcript 大小、观测成本和入口响应。

结果情况模型看到的内容完整内容在哪里
小于单结果上限完整 text/JSON/content blocktool result 的 canonical event
超限且有 ArtifactStore说明、有限预览、artifact 引用和大小按用户/session scope 保存的 artifact
超限但不能 spillUTF-8 安全截断加明确标记没有假装存在的完整副本
一批合计超限再次按 batch budget 分配每个结果额度每个结果自己的 spill（如果可用）

Artifact 引用不是无条件公开的 URL：读取时仍需按调用 scope 再次核对。Slack 展示时可以隐藏完整参数和结果，但这不改变模型看到的内容，也不替代 transcript 的审计权限。

重复调用和外部副作用怎样收敛

系统提供三层不同强度的保护，不能把它们混称为“Exactly once”。

调用级复用同一 turn 里已有 ToolCallCompleted/Failed 时，Runtime 不再次派发相同 CallID。它依赖 transcript 已经保存结果。
执行编号Call.ExecutionID 由 turn 和 call 组成。工具可以把它传给下游的 idempotency key，前提是下游真正支持该语义。
恢复中的 unknown只有 ToolCallStarted 没有结果时，恢复写入 execution_interrupted，不自动重做；下一轮可以先查询上游。
重复失败熔断同一 session 内相同工具和规范化参数连续失败达到阈值时，阻止模型无效循环。它是 liveness/cost guard，不是权限策略。
没有跨系统事务外部 API 成功和 transcript append 不能放进同一个 PostgreSQL 事务。要实现更强的业务语义，工具需要幂等写入、结果查询、outbox/inbox 或人工补偿中的至少一种。

新增工具的最小设计清单

  1. 定义真实效果。把读取、workspace write、external write、network 和 privileged 全部写进 Effects；不要因为“通常只读”而隐藏偶发写入。
  2. 定义严格 schema。参数结构、枚举、大小和必填项要能在 Execute 前验证；工具仍要做业务级目标校验。
  3. 决定 exposure 和 surface。重工具默认 deferred；依赖未连接时不注册；Surface 只决定产品可见性，不当作授权。
  4. 证明并发属性。只有真实独立、可安全重叠的读操作才标 parallel；包含用户暂停或必须单独执行的调用标 exclusive。
  5. 定义超时和结果上限。给下游调用设置 timeout，限制日志/文件大小，必要时接入 ArtifactStore，并返回稳定 ErrorCode。
  6. 处理未知副作用。在实际动作前允许 Runtime 写 ToolCallStarted；传 ExecutionID 到支持幂等的下游，准备查询接口或补偿流程。
  7. 覆盖组合测试。至少测试 policy deny/approval、取消、panic、空结果、超大结果、重复恢复、路径/网络边界和并发重叠。

工具相关的生产推演

一个只读工具把数据库连接池打满

原因parallel 只限制 Runtime 的调用数，工具内部或下游 client 可能再次 fan-out；共享读锁不代表下游没有连接上限。

动作同时观察 MaxParallelToolCalls、工具内部 worker、pool wait、调用 p95 和 provider API rate limit，按最窄的资源调节。

模型不断重复同一个失败调用

先查工具返回的 ErrorCode、参数规范化是否稳定、是否真的有结果事件，以及 circuit breaker 是否只在当前 turn 生效。

动作修复可操作的结构化错误；保留重复失败保护，但不要把它当成权限拒绝或业务成功。

“批准”后执行了不同于用户看到的参数

风险如果 UI 允许后续模型重新生成参数，用户批准的动作和实际动作已经不是同一件事。

动作按原始 TurnID + ToolCallID 取回参数并重新做 policy 检查；批准记录与结果必须关联同一个 call。

工具结果变小后模型反而做出错误结论

先查Truncated、Spill、artifact 可读性、批次总预算和模型是否看到了完整错误码。

动作让工具返回摘要、关键字段和稳定引用，不要只盲目提高 inline budget；大结果应能被按权限重新读取。
