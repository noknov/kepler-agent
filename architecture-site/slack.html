ADAPTER / SLACK

Slack 接入

Slack 是共享执行核心之外的一层适配器。它验证平台请求、把消息线程映射为会话、整理附件和追加输入，再将 Core 产生的事件投影为 Slack 回复。模型循环、工具调度和终态判断仍由 Core 完成。

适配契约

Slack 输入Core 契约边界
team、channel、thread、user身份与执行作用域平台标识只作为作用域数据，不进入 Runtime 控制流
event_id稳定请求来源用于入口幂等，不替代会话事件序号
消息、历史、附件统一内容块外部文本始终是不可信用户内容
线程中新消息追加输入源先持久化，再在稳定执行边界加入
流式消息接口事件接收器呈现失败不改变 Core 中已经确认的执行事实

接收路径

  1. 读取有限大小的原始请求体签名针对原始字节计算，不对解析后的 JSON 重新编码。
  2. 检查时间与签名拒绝超出时间窗口的请求，并使用常量时间比较验证 HMAC。
  3. 按事件编号持久化相同事件收敛到同一条 inbox 记录；写入成功后 HTTP 生命周期即可结束。
  4. 工作进程认领并续期模型执行与平台回调解耦，认领、重试和接管由持久状态控制。
  5. 组装 Core 请求解析身份、线程历史、附件、工具作用域和输入来源，然后调用共享 Runtime。

线程与会话

频道和消息线程共同确定连续会话。首次处理时，适配器读取有限历史并转换为内部消息；之后的事件从会话记录继续。Slack 事件编号标识本次入口请求，会话事件序号负责内部顺序，两者不能混用。

追加输入会话正在执行时，新消息先写入持久输入队列。路由策略决定它加入当前执行还是排到下一轮；Redis 只负责唤醒，不承担权威队列。

附件处理

适配器检查文件类型、大小和当前安装权限，再将附件转换为图片内容、提取文字或受控文件引用。原始平台文件对象和访问令牌不会进入模型上下文。下载失败形成分类错误，不伪装成空附件。

输出投影

文字片段
跨片段脱敏器确认安全边界后进入发送缓冲。
首次可见内容
此时才建立 Slack 原生流，避免纯工具阶段产生空白消息。
流式失败
保留 Core 的完整答案，结束时回退到普通消息；投递状态单独记录。
消息过长
按段发送并维护代码围栏状态，避免 Markdown 语义跨段损坏。
结果不确定
Slack API 与数据库没有共同事务；超时后先查询既有投递，不能直接重复外部写入。
