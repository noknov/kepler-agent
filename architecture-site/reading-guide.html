概念与标识

同一项任务会经过用户、会话、执行、网络和工具多个层级。先区分这些对象，再解释它们的标识和状态，可以避免把“请求已收到”“模型已返回”和“外部动作已完成”混成同一件事。

核心术语

入口适配器接收具体产品的输入，产品配置选择依赖，执行器推进模型和工具步骤。这三个名称描述不同职责，可能运行在同一进程，不必理解为三台服务器。

会话是一段连续对话的归属；一次执行是其中一个输入的处理生命周期；模型轮次是一次逻辑模型请求；网络尝试是其中一次实际提供方调用。一个执行可以包含多个轮次，一个轮次又可以因重试包含多个尝试。

名称英文定义
入口适配器surface验证输入身份，接收请求并呈现结果。
产品配置profile选择执行依赖、存储、凭据、工具和策略。
执行器runtime推进模型与工具循环，维护执行事件与终态。
会话session连续对话及历史、锁和输入路由的归属。
一次执行turn从输入建立到终态的一次执行生命周期。
模型轮次model step构造上下文并取得一次逻辑模型响应。
网络尝试attempt一次实际提供方请求，包含重试和备用路径中的尝试。
会话事件记录transcript用于历史投影和恢复的只追加执行记录。
运行投影run / step projection从执行事件生成的查询状态。
处理权ownership / lease在指定范围内认领并推进工作的权利。
未知结果unknown outcome无法确认操作完成或未发生的状态。

说明示例

同一调查中的不同对象

用户先要求检查登录失败，随后补充解释。两条输入可以属于同一会话，但对应不同执行。第一项调查可能先读文件、再运行测试、最后答复，因此包含多个模型轮次。

运行测试前的模型请求若发生临时失败并重试，则该轮次又包含多次网络尝试。不能把第二次 attempt 当作第二项用户任务，也不能把第二项用户任务当成第一次的重复网络请求。

常用机制词的具体含义

持久化是把状态写入重启后仍可读取的存储。函数已经返回、日志已经打印或界面已经显示，不一定证明对应业务记录已经提交。

幂等是重复提交同一次操作时，不再产生额外效果。例如，存储用稳定事件身份拒绝重复插入。它只约束采用该机制的边界，不能自动约束另一个外部系统。

事务把一组存储操作作为一个提交单位。这里的数据库事务不会把网络另一端的文件修改或 API 写入一起包进去，因此两边之间仍可能有失败窗口。

租约是带到期条件的认领。它允许处理者失联后由别人接手，但旧处理者仍必须停止，后续确认也要匹配当前所有者。它不同于只按进程退出释放的操作系统文件锁。

标识作用域

标识用于把不同层级的记录连起来，不是权限本身。知道某个会话 ID，只能指向一个对象；入口仍须检查当前用户是否有权访问它。

同名字段也要按所属存储解释。入口 event ID 用于平台投递去重，执行事件 ID 用于事件追加；会话序号用于排序，不能与 ID 混为同一用途。

标识对应对象不能替代
event_id一次入口或执行事件，按所属存储解释会话内顺序
session_id会话用户授权凭证
turn_id一次执行每次模型网络尝试
attempt_id提供方网络尝试工具副作用确认
call_id / execution_id工具调用与实际执行身份下游完成证明

工具调用还要区分模型提出的调用身份与实际执行身份。稳定执行标识可以传给支持幂等的下游，但只有下游真的使用该标识约束重复写入时，才形成对应保证。

说明范围

架构说明解释模块为何划分、数据怎样流动和失败时怎样处理。具体配置、安装与部署命令由所属运行指南维护；这里引用实现与测试，是为了让机制可以核对。

代码中的 step 需要结合上下文理解：执行循环中可以指模型轮次，运行投影中也可能表示工具步骤。文档会在相关位置说明对象，不能只凭一个英文词推断语义。

同样，持久化、恢复、幂等和隔离都需要说明范围。一次数据库提交不会把外部 API 纳入同一事务，本地沙箱通过也不能证明托管部署具有相同边界。
