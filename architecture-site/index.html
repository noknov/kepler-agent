共享执行核心

一个与入口协议无关的 Agent Core：接收规范化请求，重建上下文，调用模型，执行经过策略检查的工具，并把全过程写成可恢复的事件。入口只负责协议、身份和呈现，不拥有另一套执行循环。

模型循环 单一实现状态 事件驱动工具 策略先行恢复 基于事实

先看两条平面：控制面与执行面

生产系统里最容易混淆的是“用户已经发出请求”“系统已经接受请求”“模型已经完成判断”“外部动作已经生效”和“用户已经看到回复”。这些是不同事实，分别由入口、队列、Runtime、工具和消息投影负责。

边界输入输出实现位置
Ingress平台请求、用户身份、原始事件经过认证的 inbox/input 记录packages/surfaces、packages/eventinbox
Runtime规范化请求、上下文依赖、预算终态、用量、生命周期事件packages/agent/runtime
Model统一消息、工具定义、提示片段内容块、工具请求、结束原因packages/agent/model、packages/providers
Tool名称、参数、执行作用域、策略结构化结果或分类错误packages/agent/tool、packages/tools
Transcript已确认发生的生命周期事实有序历史、恢复依据、查询投影packages/agent/transcript、各 profile store

一个请求至少有六种身份

身份范围用途不能替代什么
event_id入口投递Slack inbox 去重、平台重试收敛不能当作会话内顺序
session_id连续对话和执行归属会话锁、历史、输入队列不能表示一个 turn 的完成
turn_id一次用户请求/恢复请求模型循环、审批和消息关联不能代表每次模型网络尝试
step_id一次可观测步骤运行详情、耗时、错误和用量不能作为事件序号
attempt_id一次提供方尝试重试、fallback、熔断统计不能代表模型已经产生可见文本
call_id / execution_id工具请求和实际执行调用去重、未知结果调查、外部幂等不能证明外部系统一定完成
排障口诀：先问“我手里的 ID 属于哪一层”，再决定查 inbox、session transcript、run step、model attempt 还是外部请求。用 event_id 去查工具重复，通常会把真正的问题藏起来。

一轮执行怎样推进

  1. 取得会话处理权同一 session 只允许一个有效执行者推进，避免两个分支同时消费同一份历史。
  2. 恢复未完成事实读取有序事件；工具开始但没有结果的调用标记为中断/未知，不能在恢复时假装从未发生。
  3. 建立 turn 与输入保存 turn_started 和 user_input，再把前序事件投影成当前模型上下文。
  4. 生成模型请求模型适配器进行有限次数的提供方尝试，记录请求、attempt、流式完成或分类失败。
  5. 调度工具先做目录查找、参数校验、能力策略和作用域检查；只读调用可以受控并发，修改调用按安全边界串行。
  6. 提交事实模型消息、工具开始与结果、压缩和终态先进入记录，再由投影层生成运行列表与界面状态。
  7. 判断是否继续工具结果或追加输入触发下一轮；完成、等待输入、取消、预算耗尽和错误都形成明确终态。

必须保持的不变量

Core 不依赖入口

允许入口把身份、消息、附件和输出接收器转换成核心契约。
禁止Runtime 内读取平台请求、调用平台 SDK 或维护界面状态。

事件只记录已确认事实

权威用户输入、完整模型消息、工具生命周期、批准、压缩和请求终态。
派生运行摘要、步骤列表、费用、状态提示和健康汇总，可从权威记录重建。

策略高于工具描述

描述告诉模型工具能做什么，不构成授权。
执行工具元数据、服务端允许列表、工作区边界与沙箱共同决定动作能否发生。

恢复不猜测外部副作用

已知有完成记录的动作可以复用其结果。
未知开始后中断的外部写入保持未知，必须查询上游或人工确认，不能盲目重试。

呈现失败不回滚执行事实

执行turn_completed、tool_result 和费用等事实先写入权威记录。
呈现Slack 流式更新、运行投影或指标写入失败时，单独补偿其投影，不重跑已经完成的模型动作。

设计落地时必须回答的问题

问题文档中的落点
进程崩溃后从哪里恢复？会话事件、inbox/input 租约和可重建的运行投影；见 可靠性。
工具超时后能否安全重试？看 ToolCallStarted、执行身份和外部幂等能力；见 工具。
429、空响应和流式半截怎样区分？按模型逻辑请求与 attempt 分层记录；见 模型与上下文。
为什么用户看到“已收到”却很久没回复？分别检查入口、收件箱、租约、会话锁、模型、工具和 Slack 投递；见 生产推演。
子任务结果能否直接信任？子任务是隔离执行和报告来源，主任务仍须按证据核验；见 委派。

组装关系

profile
├── runtime config
├── model adapter
├── tool catalog
│   ├── descriptors
│   ├── executors
│   └── capability policy
├── transcript store
├── input source
├── event sink
└── surface adapter
    ├── Slack ingress / delivery
    └── observability / management

产品层只选择这些依赖并建立作用域。共享 Runtime 不知道模型密钥来自哪里、数据库如何部署，也不假设请求来自哪一种界面；入口适配器负责把平台语义转换成稳定的 Core 契约。
