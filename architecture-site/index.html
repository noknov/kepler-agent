共享执行核心

一个与入口协议无关的 Agent Core：接收规范化请求，重建上下文，调用模型，执行经过策略检查的工具，并把全过程写成可恢复的事件。入口只负责协议、身份和呈现，不拥有另一套执行循环。

模型循环 单一实现状态 事件驱动工具 策略先行恢复 基于事实

核心边界

先用四个接口理解代码归属。任何新的模型能力、工具类型或接入方式，都应落在其中一个明确边界内。

边界输入输出实现位置
Runtime请求、上下文依赖、预算终态、用量、事件packages/agent/runtime
Model统一消息、工具定义内容块、工具请求、结束原因packages/agent/model、packages/providers
Tool名称、参数、执行作用域结构化结果或分类错误packages/agent/tool、packages/tools
Transcript已确认发生的生命周期事实有序历史、恢复依据、查询投影packages/agent/transcript

执行循环

  1. 取得会话处理权同一会话在一个稳定点上继续，避免两个执行分支同时消费同一份历史。
  2. 恢复并投影上下文读取有序事件，补全上次中断的未知状态，再按完整交互分组生成本轮上下文。
  3. 请求模型提供方适配器把统一消息转换成具体协议，并把流式内容、工具请求、用量和错误映射回来。
  4. 调度工具先做目录查找、参数校验、能力策略和作用域检查；只读调用可以受控并发，修改调用保持确定顺序。
  5. 提交事实模型消息、工具开始与结果、压缩和终态先进入记录，再由投影层生成运行列表与界面状态。
  6. 判断是否继续工具结果或追加输入触发下一轮；完成、等待输入、取消、预算耗尽和错误都形成明确终态。

必须保持的不变量

Core 不依赖入口

允许入口把身份、消息、附件和输出接收器转换成核心契约。
禁止在 Runtime 内读取平台请求、调用平台 SDK 或维护界面状态。

事件只记录已确认事实

权威用户输入、完整模型消息、工具生命周期、批准、压缩和请求终态。
派生运行摘要、步骤列表、费用、状态提示和健康汇总，可从权威记录重建。

策略高于工具描述

描述告诉模型工具能做什么，不构成授权。
执行工具元数据、服务端允许列表、工作区边界与沙箱共同决定动作能否发生。

恢复不猜测外部副作用

已知有完成记录的动作可以安全重放其结果。
未知开始后中断的外部写入保持未知，必须查询上游或人工确认，不能盲目重试。

组装关系

profile
├── runtime config
├── model adapter
├── tool catalog
│   ├── descriptors
│   ├── executors
│   └── capability policy
├── transcript store
├── input source
└── event sink

产品层只选择这些依赖并建立作用域。共享 Runtime 不知道模型密钥来自哪里、数据库如何部署，也不假设请求来自哪一种界面。
