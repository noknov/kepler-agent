03 / REQUEST LIFECYCLE

Slack 请求链路

1 · 验证校验签名、时间戳和请求大小
2 · 持久化按 event_id 写入 PG inbox 去重
3 · 领取Worker 原子获取带期限的租约
4 · 执行锁定会话，驱动 Core 与工具
5 · 完成追加 Transcript 并回复 Slack

入口与入队

Gateway 校验 Slack 请求后，将事件写入 slack_event_inbox 并返回成功。Redis 发布新事件通知；Worker 同时保留 PostgreSQL 轮询路径。

租约、续租与恢复

Worker 领取任务后写入 claim_owner 和 claim_until。执行期间按周期续租；Worker 崩溃后租约自然过期，其他实例可以恢复事件。完成、失败和续租都校验当前 owner，防止旧 Worker 覆盖新 Worker。

投递语义：这是至少一次处理，不是分布式“恰好一次”。如果 Slack 回复成功后、inbox 完成标记前进程崩溃，极小窗口内仍可能出现重复回复。

会话串行化

Hosted v2 使用 PostgreSQL advisory lock 串行化同一个 Slack thread 的 turn。Canonical transcript 在同一 session 下按 sequence 追加。

Steering、Queue 与取消

用户可在 App Home 选择将运行中的新消息注入下一模型步骤，或排队为后续 turn；取消会终止当前 context。活动运行的 owner worker 记录在 Redis，其他实例通过控制频道转发输入或取消请求。

04 / EXECUTION ENGINE

v2 Runtime

共享 runtime 管理 turn 生命周期、上下文投影、模型调用、工具执行、steering 和终止状态。产品 profile 通过适配器提供模型、工具、policy、transcript、artifact 和事件 sink。

Runtime

Turn 边界

同一 session 的 turn 串行执行；每次运行生成稳定的 session、turn、event 和 tool call 标识，并追加 canonical transcript。

Loop

模型—工具循环

投影上下文、调用模型、执行允许的工具、记录结果并继续，直到完成、取消、达到限制或等待审批。

每步执行

  1. 检查取消状态，并把新到达的 steering 写入 transcript。
  2. 从 transcript 投影有界模型上下文，必要时调用 compactor。
  3. 使用 canonical message 和 tool schema 调用模型适配器。
  4. 经 policy 判定后执行工具，并记录调用、结果或失败。
  5. 检测重复工具调用、模型错误、空响应、输出截断和最大步骤限制。

终止与恢复

Runtime 使用明确的 completed、canceled、model_error、max_steps、pending_approval、empty_response 和 loop_detected 状态。可重试模型错误使用有界退避；输出截断时追加继续指令；每种终止结果都写入 transcript。

07 / CANONICAL TRANSCRIPT

Canonical Transcript

v2 使用 provider-neutral、append-only 事件记录 session 和 turn。模型消息、stream event、工具调用、工具结果、steering、compaction 与终止状态使用同一套结构。

session_startedSession 建立
turn_started一次请求开始
model / tool events消息、增量、调用和结果
compaction_created记录上下文压缩
turn_*完成、失败或取消

Local profile 写入每个 session 的 JSONL 文件。Hosted profile 将 canonical 事件写入 agent_transcript_events，并用 PostgreSQL advisory lock 分配 session 内单调 sequence。

08 / DATA & CONCURRENCY

数据与并发

存储职责故障后的行为
PostgreSQLSession、Run、Step、Feedback、Spill、Inbox、Protocol Events、Reminder、User Preferences不可用时拒绝需要持久状态的工作
Redis唤醒、缓存、去重、活动 owner、跨 Pod 控制、全局计数部分路径 fail-open 或退化为 PG 轮询

运行记录

Canonical transcript 写入 agent_transcript_events；观测投影将聚合摘要写入 agent_runs，模型与工具步骤写入 agent_run_steps，反馈写入 agent_run_feedback。

Schema 管理

DDL 是创建或改变数据库结构的 SQL，例如 CREATE TABLE 和 ALTER TABLE。运行时代码不执行 DDL，只做只读的完整性检查。当前目标结构集中在 schema/postgres.sql，数据库升级由 operator 或部署仓库中的轻量 migration 流程负责。

并发控制

进程内 semaphore 限制单 Worker 并发；Redis 计数器近似限制集群并发；PG advisory lock 串行化同一 Session。它们分别解决资源上限、跨 Pod 总量和会话一致性。

03 / REQUEST LIFECYCLE

Slack request flow

1 · VerifySignature, timestamp, and size
2 · PersistDeduplicate by event_id in PG
3 · ClaimWorker obtains a timed lease
4 · ExecuteLock session, run v2 and tools
5 · CompleteAppend transcript and reply

Leases and recovery

A claim records claim_owner and claim_until. The worker renews the lease while executing. After a crash, the lease expires and another worker recovers the event. Completion, failure, and renewal are owner-checked.

Delivery semantics: processing is at-least-once, not distributed exactly-once. A crash after an external Slack write but before inbox completion leaves a narrow duplicate-reply window.

Session serialization

Hosted v2 serializes turns for the same Slack thread with a PostgreSQL advisory lock. The canonical transcript appends events by sequence within that session.

Steering, queueing, and cancellation

App Home lets each user inject active-turn input before the next model step or queue it as a later turn. Cancellation stops the current context. Active-run ownership lives in Redis so another worker can forward input or cancellation to the owner.

04 / EXECUTION ENGINE

v2 Runtime

The shared runtime manages turn lifecycle, context projection, model calls, tool execution, steering, and termination. Product profiles provide model, tool, policy, transcript, artifact, and event-sink adapters.

Runtime

Turn boundary

Turns in one session run serially. Each run assigns stable session, turn, event, and tool-call identifiers and appends a canonical transcript.

Loop

Model–tool loop

Project context, call the model, execute allowed tools, record results, and continue until completion, cancellation, a limit, or pending approval.

Each step

  1. Check cancellation and append new steering to the transcript.
  2. Project bounded model context and invoke the compactor when required.
  3. Call a model adapter with canonical messages and tool schemas.
  4. Apply policy, execute tools, and record calls, results, or failures.
  5. Detect repeated calls, model errors, empty output, truncation, and step limits.

Termination and recovery

The runtime records completed, canceled, model_error, max_steps, pending_approval, empty_response, and loop_detected states. Retryable model errors use bounded backoff; truncated output adds a continuation instruction; every outcome is appended to the transcript.

07 / CANONICAL TRANSCRIPT

Canonical transcript

v2 records sessions and turns as provider-neutral, append-only events. Model messages, stream events, tool calls and results, steering, compaction, and termination share one structure.

session_startedSession begins

model / tool eventsMessages, deltas, calls, results

The local profile writes one JSONL event log per session. The hosted profile writes canonical events to agent_transcript_events and uses a PostgreSQL advisory lock to allocate monotonic session sequences.

Run records

Runtime code executes no DDL; it only verifies required tables. schema/postgres.sql is the current contract, while operators or the deploy repository's lightweight migration flow own upgrades.

A local semaphore limits each process, a Redis counter approximates the cluster total, and a PG advisory lock serializes a session.

09 / SAFETY BOUNDARY

Identity

Filesystem

Workspace boundary

Commands

argv execution

Boundary

Sandbox boundary

The current controls are application-level policies, not process, container, or kernel isolation.

The canonical transcript records tool calls, completion, failure, and local approval requests and outcomes.

Public HTTP clients reject localhost, private, and special-use addresses and re-check resolved IPs. Redaction removes tokens, Authorization headers, private keys, and absolute workspace prefixes from logs and errors.

Stop claiming new work, wait for active events, then close HTTP and background tasks within deadlines.

Recovery

Retry and dead letter

Backoff, jitter, bounded attempts, and expired-lease recovery protect the inbox.

Evidence

Durable transcript

Hosted v2 records turns, model deltas, tool calls and results, errors, and termination by session sequence.

The worker exposes /livez, /readyz, loopback-only /drain, and /metrics. The Slack inbox reports queue depth, lease loss, dead letters, queue-full events, and completion counts.

The hosted v2 transcript is durable. Aligning run and cost views with v2 usage and tool traces remains engineering work.
